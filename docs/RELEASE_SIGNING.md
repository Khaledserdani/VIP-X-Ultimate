# إعداد توقيع إصدار VIP X Ultimate

لا يمكن اعتبار APK إصداراً نهائياً قبل توقيعه بمفتاح Release ثابت تملكه أنت.

## احتفظ بالمفتاح

1. أنشئ ملف keystore محلياً على جهاز موثوق باستخدام Java `keytool`.
2. احتفظ بنسخة احتياطية آمنة من ملف keystore وكلمات المرور واسم alias.
3. لا ترفع ملف keystore إلى GitHub، ولا تضع كلمات المرور في ملفات المشروع أو المحادثات.
4. فقدان المفتاح قد يمنع تثبيت تحديثات مستقبلية فوق النسخة المنشورة بالمفتاح نفسه.

## أسرار GitHub المطلوبة

من إعدادات المستودع افتح Settings → Secrets and variables → Actions، ثم أضف:

- `VIP_RELEASE_KEYSTORE_BASE64`: محتوى ملف keystore بعد تحويله إلى Base64 في جهازك.
- `VIP_RELEASE_STORE_PASSWORD`: كلمة مرور مخزن المفاتيح.
- `VIP_RELEASE_KEY_ALIAS`: اسم المفتاح داخل المخزن.
- `VIP_RELEASE_KEY_PASSWORD`: كلمة مرور المفتاح.

لا ترسل هذه القيم إلى أي شخص. يستخدم Workflow هذه الأسرار مؤقتاً أثناء بناء Release، ولا يحفظ ملف keystore في المستودع.

## بناء الإصدار

بعد وصول Workflow إلى الفرع الافتراضي للمستودع وإعداد الأسرار، يمكن تشغيل `VIP X Ultimate Release` يدوياً أو إنشاء tag يبدأ بـ `v`.

يتحقق Workflow من:
- نجاح توقيع APK والتحقق منه بواسطة `apksigner`.
- معرّف الحزمة `com.vipx.ultimate`.
- الإصدار الحالي `2.3.3` ورقم البناء `10`.
- بصمة APK، ثم يرفع ملف Release كـ Artifact لمدة 30 يوماً.

قبل إصدار تحديث لاحق، ارفع `versionCode` و`versionName` وفق سياسة الإصدارات، مع استخدام keystore نفسه.
