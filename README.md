# VIP X Ultimate

تطبيق Android أصلي باستخدام Kotlin وJetpack Compose، بواجهة عربية RTL ومعرّف الحزمة `com.vipx.ultimate`.

## خط أساس إعادة البناء 2.0.0
- واجهة رئيسية واحدة واضحة؛ **لا نعتمد تقسيم الشاشة إلى نصفين كميزة أو كواجهة رئيسية**.
- تحميل قائمة التطبيقات في الخلفية حتى لا تتجمد الواجهة عند التشغيل.
- تأجيل حساب SHA-256 إلى طلب المستخدم، وعدم قراءة ملفات APK كلها عند بدء التطبيق.
- عرض اسم التطبيق والحزمة والإصدار والحجم والتواريخ والصلاحيات المعلنة.
- بحث سريع بالاسم أو اسم الحزمة.
- فتح التطبيق وإعداداته من صفحة التفاصيل.
- نسخ احتياطي ZIP يجمع APK الأساسي وكل ملفات split اللازمة للتطبيقات متعددة الملفات.
- شاشة مساعد سحابي مستقلة، ورمز الوصول يبقى في الذاكرة فقط.

## دستور المنتج والمهام المثبتة
هذه متطلبات المنتج التي يجب أن تبقى في المشروع ولا تُحذف عند إعادة التصميم. لا يعني إدراج بند هنا أنه منفّذ؛ حالة التنفيذ موضحة:

### الأساس المنفّذ في 2.0.0
- [x] تطبيق جديد مستقل، Kotlin/Android Native، وليس تعديلاً لتطبيق آخر.
- [x] واجهة عربية RTL وبنية رئيسية واحدة، دون فرض تقسيم الشاشة.
- [x] فحص بيانات التطبيقات القابلة للظهور لأندرويد في الخلفية.
- [x] بحث، تفاصيل، فتح التطبيق، والانتقال إلى إعداداته.
- [x] حساب SHA-256 عند الطلب فقط.
- [x] تصدير نسخة APK احتياطية تشمل base وsplit APK.
- [x] واجهة المساعد السحابي واتصال HTTPS؛ تفعيل الذكاء فعلياً مشروط بإعداد الخادم ومفاتيحه.

### مهام المنتج التالية — مثبتة وغير مدّعاة الإنجاز
- [ ] **مركز تحكم موحّد:** نقطة دخول واحدة للأدوات والمهام، مع اختصارات سريعة قابلة للتخصيص.
- [ ] **محلل التطبيقات الذكي:** تحليل معلومات التطبيق وملفاته وصلاحياته ومؤشرات السلامة المتاحة، مع شرح مفهوم ودرجة ثقة مبررة؛ لا ادعاء كشف برمجيات خبيثة دون محرك وفحوص موثوقة.
- [ ] **مهندس الذكاء الاصطناعي:** استقبال طلب المستخدم، اقتراح تغييرات على مشروع أو إعدادات مسموح بها، عرض الفروقات والمعاينة أولاً، وعدم تطبيق التغيير قبل موافقة صريحة.
- [ ] **محرك بناء واختبار:** بناء المشاريع المدعومة وتشغيل الاختبارات وعرض السجلات والنتيجة؛ لا يُعلن النجاح إلا بعد نجاح الاختبارات فعلياً.
- [ ] **أدوات عائمة واختصارات:** أدوات سريعة اختيارية، مع احترام إذن الظهور فوق التطبيقات وحدود Android؛ لا تفعيل خفي ولا تجاوز لقيود النظام.
- [ ] **صورة داخل صورة عند الدعم:** استخدام PiP للسيناريوهات التي يسمح بها Android والتطبيق المستهدف، وليس فرضها على كل تطبيق.
- [ ] **دعم سيناريوهات متعددة التطبيقات والألعاب:** أدوات مساعدة ومعلومات واختصارات مسموحة؛ لا حقن أو تعديل ذاكرة أو تجاوز حماية أو مشتريات أو اشتراكات.
- [ ] **تكامل GitHub وChatGPT:** ربط آمن ومصرّح به لمراجعة المشاريع والملفات وطلبات البناء؛ مع إبقاء الأسرار خارج المستودع والتطبيق.
- [ ] **سجل مهام وحالة واضح:** لكل ميزة حالات: مخطط لها، قيد التنفيذ، اجتازت الاختبار، أو متوقفة مع سبب؛ لا تُحوّل المهمة إلى مكتملة لمجرد ظهور زر لها.

## قيود ثابتة
- لا ميزات VIP وهمية، ولا فتح خدمات مدفوعة أو ميزات محمية على خوادم الغير.
- لا تجاوز لحماية التطبيقات أو DRM أو أنظمة الدفع والاشتراكات.
- لا قراءة لبيانات التطبيقات الخاصة أو تعديل تطبيقات الآخرين دون إذن.
- كل ميزة تعتمد على إذن Android يجب أن تطلبه بوضوح وتشرح فائدته، وتعمل بأقل صلاحية لازمة.
- لا تجعل تقسيم الشاشة إلى قسمين هو المنتج أو الميزة الأساسية؛ المطلوب أدوات فعلية وسريعة تخدم المستخدم.
- لا نعتبر أي ميزة مكتملة قبل تنفيذها واختبارها على جهاز حقيقي حيث يلزم.

## حدود Android والخصوصية
- الفحص المحلي يقتصر على بيانات الحزم والملفات التي يسمح Android للتطبيق بقراءتها.
- تصدير APK هو نسخة احتياطية؛ تثبيت الحزم يتطلب موافقة المستخدم ومثبت Android.
- المساعد السحابي لا يصبح فعّالاً إلا عند نشر الخادم وضبط أسرار الوصول ومفتاح مزود الذكاء الاصطناعي.
